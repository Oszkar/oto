# v0.5.1 Group Operations — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers-extended-cc:subagent-driven-development (recommended) or superpowers-extended-cc:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add group form/break (`join_group`/`leave_group`), group volume/mute (commands + read/event), and the Option D topology fast-path to oto's capability layer — the last capability release before the v0.6 UI.

**Architecture:** Mutating group SOAP terminates in `oto-wire` (the only SDK-touching crate), additively on the `Wire` trait; group-volume *events* ride the existing reactive pump (`sonos-sdk-state` exposes watchable `GroupVolume`/`GroupMute`, `Scope::Group`, coordinator-routed like AVTransport); the topology fast-path reuses the already-hardened `EventPump::spawn`/`Drop` via an SSDP-skipped respawn. A hardware spike gates everything; full re-discover (Option A) stays as the guaranteed refresh fallback.

**Tech Stack:** Rust workspace (`oto-core`/`oto-wire`/`oto-mock`/`oto-app`/`oto_native`), `sonos-api =0.5.2` + `sonos-sdk-state`/`sonos-sdk-event-manager =0.5.2`, FRB v2, Flutter + Riverpod 3 (codegen).

**Spec:** `docs/superpowers/specs/2026-06-04-v0.5.1-group-operations-design.md`.

**Process note (proportional):** Per the spec's "intermediate, less documented" framing, the SOAP/Option-D implementation bodies are written here as concrete skeletons against the *confirmed* `=0.5.2` builders, with the 3 genuinely hardware-dependent unknowns (exact `SetAVTransportURI` request fields, coordinator-leave semantics, in-place vs respawn for Option D) explicitly flagged `⟢ SPIKE-CONFIRMS` rather than fabricated.
```rust
fn join_group(&self, speaker: &SpeakerId, coordinator: &SpeakerId) -> Result<(), WireError> {
    let mut g = lock!(self);
    if !g.speakers.contains_key(speaker) { return Err(WireError::NotFound(speaker.to_string())); }
    if !g.speakers.contains_key(coordinator) { return Err(WireError::NotFound(coordinator.to_string())); }
    if let Some(err) = g.command_errors.get(speaker) { return Err(err.clone()); }
    // Reassign speaker's coordinator to `coordinator`'s group.
    let coord = g.member_to_coord.get(coordinator).cloned().unwrap_or_else(|| coordinator.clone());
    g.member_to_coord.insert(speaker.clone(), coord);
    Ok(())
}
fn leave_group(&self, speaker: &SpeakerId) -> Result<(), WireError> {
    let mut g = lock!(self);
    if !g.speakers.contains_key(speaker) { return Err(WireError::NotFound(speaker.to_string())); }
    if let Some(err) = g.command_errors.get(speaker) { return Err(err.clone()); }
    g.member_to_coord.insert(speaker.clone(), speaker.clone()); // standalone
    Ok(())
}
```

```rust
pub(crate) fn join(client: &SonosClient, joiner_ip: &str, coordinator_id: &SpeakerId) -> Result<(), WireError> {
    let uri = format!("x-rincon:{}", coordinator_id.as_str());

    client.execute_enhanced(member_ip, op).map(|_| ()).map_err(control::map_sdk_err)
}
```

## Task 4: Option D — topology fast-path

**Goal:** Replace the post-regroup full re-discover with the SOAP-only `refresh_topology()` that rebuilds pump routing (per the spike's chosen approach), covering RenderingControl + AVTransport + GroupRenderingControl subscriptions; full re-discover stays as fallback.

**Files:** `native/crates/wire/src/adapter.rs` + `events.rs` (the rebuild), `native/crates/app/src/lib.rs` (a `refresh_topology` entry that re-installs topology + re-pairs the pump), `app/lib/src/state/topology.dart` + `grouping.dart` (Dart swap). Tests in wire + `live_grouping.rs`.

**Acceptance Criteria:**
- [ ] `refresh_topology()` rebuilds (or atomically updates) the event pump's routing so group-addressed `Playback`/`Track`/`GroupVolume` route to the **new** coordinator with no drop — per the spike's Approach 1 (in-place) or 2 (respawn).
- [ ] On `refresh_topology` error, the path falls back to a full re-discover.
