# v0.6.4 - Mute + honest failure - Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Close the v0.6 UI milestone by rendering the mute capability that is already plumbed end-to-end, and by making command failures visible with a working recovery path out of the unreachable state.

**Architecture:** Pure Flutter/Dart over the existing FRB surface. No Rust changes, no new FRB commands or events, no new Dart package dependencies. Mute reuses the shipped `set_mute` / `set_group_mute` commands and the `Mute` / `GroupMute` events already folded by `household_reducer.dart`. Failure surfacing adds one keep-alive Riverpod notifier that the shared `_Reconciling.send` reports into and one shell-level listener that renders a `SnackBar`. The unreachable-state trap is fixed at its root: a full SSDP discovery now clears carried-over health instead of preserving `online: false` forever.

**Tech Stack:** Flutter, Riverpod 3 (codegen via `@riverpod`), `flutter_test`. Codegen: `just gen`. Gates: `just check`, `just test`.

## Global Constraints

- **No backend work.** Do not touch `native/**`, `native/src/api.rs`, or any Rust crate. If a task appears to need a new command or event, stop and ask - it is out of scope for this milestone.
- **No new dependencies.** No additions to `app/pubspec.yaml` `dependencies:` or `dev_dependencies:`.
- **Backend-true rule holds.** Do not render shuffle, repeat, seek, queue, or EQ/Sound controls. Never fake a control and never show one disabled as a placeholder.
- **Copy style:** hyphens (`-`), never the em-dash character (U+2014). Three periods (`...`), never the ellipsis character.
- **Touch targets:** every interactive control is at least `Sizes.touchTarget44` (44 logical px) in both dimensions, using transparent hit-slop around a smaller glyph rather than a shrunken visible icon.
- **`inkFaint` is decorative only.** Never use it for load-bearing text or for the only state signal on a control.
- **Regenerate after provider changes.** Any file with a `@riverpod` annotation added or changed requires `just gen` before `just check` passes (CI enforces generated-source freshness).
- **Commit style:** Conventional Commits, enforced by the lefthook `commit-msg` hook. Never `--no-verify`.
- **Branch:** create `feat/v0.6.4-<slug>` branches off `main`; `main` is protected. One PR per task or per closely-related task pair.

```dart
  /// Flip a room's mute optimistically and fire the command. Mirrors
  /// [GroupingController.setGroupMute]: `prev` may be null (event-only field,
  /// no value seen yet), so a failed command restores null rather than leaving
  /// a fabricated value standing.
  Future<void> setMute(String speakerId, bool muted) {
    final prev = ref.read(householdProvider).rooms[speakerId]?.muted;
    _h.setOptimisticMuted(speakerId, muted);
    return send(
      () => api.setMute(speakerId, muted),
      rollback: () => _h.restoreMuted(speakerId, prev),
    );
  }
```

```dart
import 'package:flutter/material.dart';

import '../../theme/tokens.dart';
import 'oto_icon.dart';

/// The mute toggle: the volume glyph that already led every volume row, made
/// interactive. Tapping flips mute for whatever the row controls - a room
/// (`PlaybackController.setMute`) or a group master
/// (`GroupingController.setGroupMute`).
///
/// [size] is the glyph size, so each row keeps its own visual weight; the tap
/// target is always at least [Sizes.touchTarget44] via transparent hit-slop.
/// A null [muted] means no mute value has been observed yet (the field is
/// event-fed) and renders as unmuted.
class MuteButton extends StatelessWidget {
  const MuteButton({
    super.key,
    required this.muted,
    required this.enabled,
    required this.size,
    required this.color,
    required this.label,
    required this.onToggle,
  });

  /// Current mute state; null when never observed.
  final bool? muted;

  /// Whether the target can be commanded (false for an unreachable room).
  final bool enabled;

  /// Glyph size in logical px - matches the static icon this replaced.
  final double size;

  /// Glyph colour - matches the static icon this replaced.
  final Color color;

  /// What is being muted, for the tooltip and the semantic label.
  final String label;

  final VoidCallback onToggle;

  @override
  Widget build(BuildContext context) {
    final isMuted = muted ?? false;
    final action = isMuted ? 'Unmute $label' : 'Mute $label';
    return IconButton(
      tooltip: action,
      onPressed: enabled ? onToggle : null,
      padding: EdgeInsets.zero,
      constraints: const BoxConstraints(
        minWidth: Sizes.touchTarget44,
        minHeight: Sizes.touchTarget44,
      ),
      icon: OtoIcon(
        isMuted ? 'volumeMute' : 'volume',
        size: size,
        color: color,
      ),
    );
  }
}
```

```dart
/// The command-failure notice channel.
///
/// `_Reconciling.send` (commands.dart) rolls back a failed optimistic command
/// and, before v0.6.4, said nothing - so the control silently bounced back with
/// no explanation. It now reports here, and the shell's
/// `CommandFailureListener` renders the notice as a SnackBar.
///
/// The message is derived from the error VARIANT, so the app only ever claims
/// what it actually knows: a network error means unreachable, a Sonos fault
/// means the device refused, a stale id means the topology moved.
library;

import 'package:riverpod_annotation/riverpod_annotation.dart';

import '../rust/api.dart';

part 'command_failures.g.dart';

/// One failure worth telling the user about. [id] is monotonic so two
/// identical messages are still distinct values - a listener that dedupes on
/// equality must still fire for a repeat failure.
class CommandFailure {
  const CommandFailure({required this.id, required this.message});

  final int id;
  final String message;

  @override
  bool operator ==(Object other) =>
      identical(this, other) ||
      other is CommandFailure && id == other.id && message == other.message;

  @override
  int get hashCode => Object.hash(id, message);
}

/// The user-facing sentence for [e], naming [label] (a room or group name)
/// when the caller knows it.
String describeCommandError(CommandError e, String? label) {
  final who = label ?? 'that speaker';
  return switch (e) {
    CommandError_Network() => 'Could not reach $who',
    CommandError_NotFound() => '$who is no longer available - scanning again',
    CommandError_Sonos() => '$who rejected that command',
  };
}

/// The latest command failure, or null before the first one.
///
/// `keepAlive`: failures are reported from controllers that outlive any single
/// widget, and the shell listener must not miss one because no widget happened
/// to be watching.
@Riverpod(keepAlive: true)
class CommandFailures extends _$CommandFailures {
  int _seq = 0;

  @override
  CommandFailure? build() => null;

  void report(String message) {
    state = CommandFailure(id: ++_seq, message: message);
  }
}
```

```dart
    String? label,

      await op();

      // mid-drag send still in flight when the final one succeeds; if that
      // stale send then fails, neither its rollback nor its failure notice is
      // about anything the user is still doing - reporting it would claim
```

```dart
/// Renders [child] and surfaces every reported command failure as a SnackBar.

/// Lives at the shell so one listener covers every screen; the alternative
/// (each screen wiring its own) would drop notices for whichever screen forgot.
///
/// A new failure REPLACES the visible one instead of queueing behind it: a dead
/// speaker can fail several throttled sends from one volume drag, and a queue
/// would make the user dismiss the same message repeatedly.

  final Widget child;

      messenger

        ..showSnackBar(
          SnackBar(
            content: Text(next.message),
            behavior: SnackBarBehavior.floating,
            duration: const Duration(seconds: 4),
          ),
        );
    });
    return child;
  }
}
```

## Task 5: A way out of the unreachable state (#104)

Two independent defects, both pure Dart:

1. **Health never clears.** `householdFromTopology` carries `online: prev?.online ?? true` across every re-discovery. A speaker marked unreachable by one failed command stays unreachable forever, with no path back short of restarting the app. That is why #104's reporter saw no recovery after reconnecting.

   **What the fix can and cannot claim.** It is tempting to say "a full SSDP discovery only lists speakers that just answered". That is **false**, and the implementation says so: `native/crates/wire/src/adapter.rs:356-370` sweeps SSDP for candidate addresses, then loops them and `break`s on the **first** one that answers `fetch_zone_group_state` - the whole speaker list is built from that single device's ZoneGroupState (`to_snapshot(groups)`). A speaker that is off or unreachable can still appear in that list, because the responding speaker reports it. Per-speaker reachability evidence is not available on the Dart side, and obtaining it would be backend work this milestone forbids.

   So the fix is an **optimistic reset, justified by user intent rather than by evidence**: a full `discover()` is either app start or the user pressing "Scan network", and in both cases the right behaviour is to stop asserting a stale unreachable flag and let the next command re-establish the truth. A speaker that is genuinely still unreachable flips straight back on its next failed command - which now also produces a visible notice (Task 3). The cost of being wrong is one optimistic room for one command; the cost of the status quo is a permanently stuck UI.

   A **fast `refreshTopology()`** must NOT reset, for a different reason: it fires automatically on every regroup, so resetting there would flap a genuinely-off speaker back to "online" repeatedly with no user action behind it. The distinction the code encodes is *user-initiated scan* vs *background refresh*, not *proven* vs *unproven*.

2. **No rescan affordance when everything is unreachable.** Cached topology counts as a successful discovery, so `homeViewState` returns `HomeReady` and neither the error state nor its `Scan network` button ever renders. Fix: a distinct state for "we have rooms and every one of them is unreachable", rendered as the normal Home content plus the existing retry banner.

Plus the copy: `Powered off` is a claim the app cannot support - the only signal behind it is a command that failed with a network error.
