# v0.5.1 — Group operations (design)

Status: approved (brainstorm 2026-06-04). Transient milestone doc — retire post-release per the docs convention.
Siblings: [ROADMAP](../../ROADMAP.md) · [ARCHITECTURE](../../ARCHITECTURE.md) · [sonos-notes](../../sonos-notes.md).

## Why

v0.5.1 is the **last capability-layer release before the v0.6 UI**. The stated v0.5 goal — "finish the capability work so the UI is a pure design+build problem" — has one explicitly-deferred item (group form/break) plus one capability gap surfaced during this brainstorm (group volume). Closing both now keeps v0.6 pure design+build.

Three workstreams, gated by one mutating-SOAP spike, sequenced so the risky part can slip to a potential **v0.5.2** without blocking the shippable value.

## Scope (locked)

1. **Form/break** — `join_group` / `leave_group`.
2. **Group volume/mute** — commands **and** read/event.
3. **Topology fast-path (Option D)** — `refresh_topology` rebuilds pump routing in place, replacing the full re-discover after a regroup.

Explicit non-goals: no UI (that's v0.6); no coordinator-transfer / party-mode / group-all primitives (the UI composes those from join/leave); no seek, play-mode toggle, or relative per-speaker volume.

## Feasibility (confirmed against the `=0.5.2` pin)

Builders/properties already present in the pin — the spike validates **behavior**, not existence:

- **Join:** `av_transport::set_av_transport_uri(joiner, "x-rincon:RINCON_<coord_uuid>")`.
- **Leave:** `av_transport::become_coordinator_of_standalone_group(member)`.
- **Group vol/mute commands:** `group_rendering_control::{set_group_volume, set_relative_group_volume, set_group_mute, get_group_volume, get_group_mute}`.
- **Group vol/mute events:** `sonos-sdk-state` defines `GroupVolume(u16)` / `GroupMute(bool)` as watchable `SonosProperty` — `SERVICE = GroupRenderingControl`, `SCOPE = Group` (coordinator-routed via `initialize(topology)`, exactly like AVTransport `Playback`/`Track`). `GroupVolume::new` clamps to `0..=100`.

Implication: group-volume read+event rides the **existing reactive pump** — not a Path-B detour. The `group_management::{add_member, remove_member}` ops also exist but are **not** chosen (`add_member` needs a `boot_seq`; the `x-rincon` / `BecomeCoordinator…` AVTransport path is the battle-tested grouping primitive).

## A — Spike first (the gate)

Hardware spike on the 4-speaker LAN behind `live-tests`, before any production code. Validates:

- **Join** folds the joiner into the coordinator's group; capture the resulting `GroupId`.
- **Leave** splits a member out. **Edge to confirm:** leaving the *coordinator* of a 3+ member group — does Sonos re-elect a new coordinator for the remainder, or is a different primitive needed? This is the one edge that could change the leave design.
- **Group vol/mute** commands: proportional scaling, clamp range, `get_group_volume` read.
- **Group vol/mute events:** `watch_property_with_subscription::<GroupVolume>/<GroupMute>` on coordinators — seed + change NOTIFY latency, double-event bursts (expect Track-style last-wins dedup).
- **Option D feasibility (the big one):** can a running pump's routing be rebuilt in place — re-`initialize(new_topology)` on the live `StateManager` + add subscriptions for any newly-appeared coordinator — **without** a full re-discover? Decides **Approach 1 (true in-place)** vs **Approach 2 (SSDP-skipped pump respawn)**. Both deliver the fast-path; **full re-discover (Option A) stays as the guaranteed fallback.**

Spike output: durable findings appended to `sonos-notes.md`; go/no-go per workstream; Option D approach pick.

## B — `Wire` trait growth (additive)

```rust
// Form/break — per-speaker (Sonos primitives).
fn join_group(&self, speaker: &SpeakerId, coordinator: &SpeakerId) -> Result<(), WireError>;
fn leave_group(&self, speaker: &SpeakerId) -> Result<(), WireError>;

// Group volume/mute — by GroupId (coordinator-routed, like playback).
fn set_group_volume(&self, group: &GroupId, volume: Volume) -> Result<(), WireError>;
fn set_group_mute(&self, group: &GroupId, muted: bool) -> Result<(), WireError>;
```

`refresh_topology` already exists (v0.5); Option D promotes it from live-test-only to the production hot path — behavior change, not a new signature. `MockWire` implements all four deterministically (join/leave mutate the mock topology model; group-vol mutates mock group state), so integration tests stay LAN-free.

## C — Event/state additions (group-volume read)

- Pump registers `GroupVolume` + `GroupMute` watches per coordinator (same routing as `Playback`/`Track`).
- New `oto_core::ChangeEvent::{GroupVolume { group, volume }, GroupMute { group, muted }}`, mapped from the `group_volume` / `group_mute` upstream keys in `map_upstream_event`.
- `StateManager` caches group volume/mute per `GroupId` (alongside per-group Playback/Track).
- New `ChangeEventDto::{GroupVolume, GroupMute}` on the **existing single FRB stream** — no surface redesign (consistent with v0.4/v0.5).
- `GroupVolume(u16)` → `oto_core::Volume` via `Volume::clamped`. Apply the v0.5 last-wins ~200 ms dedup.
- *(Optional, deferred-by-default: `GroupVolumeChangeable` so the UI can disable a fixed-output slider.)*

## D — FRB command surface

Four new non-sync shims in `native/src/api.rs` (`join_group` / `leave_group` / `set_group_volume` / `set_group_mute`), delegating to `oto-app`, lock-across-SOAP like the existing 7 playback commands. **Form/break does not self-trigger a refresh** (hardware spike 2026-06-04: an immediate post-mutation re-pull races the topology settle). The mutation fires `GroupMembership` NOTIFYs exactly like an external Sonos-app regroup, so the existing v0.5 debounced topology-event path refreshes the view — there is no separate self-trigger. *(Refinement vs. this section's original "trigger a refresh directly" plan; see `docs/sonos-notes.md` § "Topology settle latency".)*

## E — Topology fast-path wiring (Option D)

The Dart `TopologyController` upgrades from *debounce → full re-discover* to *debounce → `refresh_topology()`* (SOAP-only, no SSDP). Full re-discover stays as the fallback if `refresh_topology` errors or pump-rebuild reports it could not update routing. Honors the hard guard: ships only once routing rebuild is proven (spike Approach 1 or 2). Post-regroup UX drops from ~3–5 s to ~tens of ms.

## Sequencing (risk-ordered — each its own PR + review checkpoint)

**Spike → form/break → group-vol read+event → Option D.**

- Form/break ships on the **existing Option-A re-discover** refresh, so its correctness does not depend on Option D.
- Group-vol events add `GroupRenderingControl` subscriptions per coordinator; Option D's pump-rebuild must then preserve RC + AVTransport + GroupRC subscriptions — so Option D lands **after** group-vol events (one rebuild covers every subscription type).
- **Escape hatch:** if Option D proves hard, it slips to **v0.5.2** (or v0.6) without blocking the shippable form/break + group-volume value.
