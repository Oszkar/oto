# v0.6.0 — Foundation + Home + Now Playing (design)

Status: **approved-in-brainstorm, pending written review** · Date: 2026-06-09 · Branch: `docs/v0.6-planning`

First sub-release of the v0.6 UI milestone. Builds the foundation (theming, the source-model state
architecture, the adaptive app shell, local persistence) plus the two highest-value screens — Home
and Now Playing — against the proven `Wire` + event stream + FRB surface. No capability-layer work.

Sibling docs: [ROADMAP](../../ROADMAP.md) (phased plan), the visual design system in
[`docs/design-system/`](../../design-system/handoff/HANDOFF.md) (tokens, screens, brand), and
[ARCHITECTURE.md](../../ARCHITECTURE.md) (the capability layer this binds to).

---

## 1. Scope

**This is a "backend-true core" build:** every control rendered is backed by the current `Wire` trait.
Controls in the prototype that need new backend or are out of oto's scope are **not rendered** (never
faked, never shown disabled) and are deferred to later milestones with their backend work.

### In v0.6.0
- **Theming** — design tokens → `ThemeData` (light/dark) + an `OtoColors` `ThemeExtension`; bundled
  Geist; runtime-swappable accent (teal/indigo/amber/slate).
- **State architecture** — `householdProvider` accumulating per-room/per-group state from discovery +
  the live event stream; `sourcesProvider` derived selector; optimistic, LAN-polite command updates.
- **App shell** — Home-as-hub (no tab bar); navigation to Now Playing; an adaptive scaffold
  *architected* for the v0.6.3 responsive layouts but shipping the phone layout only.
- **Persistence** — local prefs (theme mode, accent, default Home layout).
- **Home** — Cards + Stack layouts (header toggle, persisted), room card/row, merged group card,
  adaptive bottom strip.
- **Now Playing** — art, title/artist/album, read-only progress, play/pause/next/prev, group volume +
  per-room levels.

### Out of v0.6.0 (later phases)
- Group editor, Room detail → **v0.6.1**
- Settings, empty/error/loading/offline state screens → **v0.6.2**
- Tablet master-detail, desktop three-pane → **v0.6.3**

### Deferred beyond v0.6 (need new backend or out of scope)
Shuffle/repeat/seek, Queue, EQ/Sound, search, stereo pair, surround, TruePlay, add-speaker, sleep
timer, telemetry, the bottom-strip "manage all" sheet, settings sub-screens. **Not rendered** in any
v0.6.0 screen.

## 2. State & source-model architecture (the spine)

The one genuinely novel piece. The backend emits *deltas* on one stream and exposes a one-shot
`speaker_state` cache read; **group volume/mute have no getter at all** (event-only). So the Dart side
must accumulate a coherent view model. This replaces the "downstream StreamProviders" placeholder that
[`events.dart`](../../../app/lib/src/state/events.dart) notes but never built.

### 2.1 Model types (`app/lib/src/state/model/`, pure Dart)

```
RoomState   { SpeakerId id, String name, String? model, RoomKind kind,
              int? volume, bool? muted, bool online = true, GroupId groupId }
              // volume/mute are PER-SPEAKER

GroupState  { GroupId id, SpeakerId coordinatorId, List<SpeakerId> memberIds,
              PlaybackState? transport, Track? track,
              int? groupVolume, bool? groupMuted }
              // transport/track/groupVolume are PER-GROUP

Household   { Map<SpeakerId,RoomState> rooms, Map<GroupId,GroupState> groups }

Source      { String id, String label, Track? track, int memberCount }   // derived, not stored
```

- `RoomKind` (`soundbar` / `speaker` / `speakers`) is a **heuristic from `model`** (soundbar for
  Beam/Arc/Ray/Playbar; else speaker), default `speaker`. Not load-bearing; refine later.
- `Track` mirrors `TrackDto` (title/artist/album/artUri/durationSecs/...).
- `null` fields are **honest-partial cold-start** — render the design's skeleton/"—", never a fake `0`.

### 2.2 The store — `householdProvider`

One `@Riverpod(keepAlive: true)` Notifier exposing `Household`:

```
discoveryProvider ──(identity skeleton: names, models, membership, coordinator)──┐
                                                                                  ▼
changeEventsProvider ──(deltas, see reducer below)───────────────────────────► Household
```

- **Identity from discovery, live state from events.** On a new `Topology` it rebuilds the
  room/group skeleton (names, models, membership, coordinator = `group.coordinator`, members =
  `group.members`) but **preserves** known per-speaker `volume`/`muted` for speakers that persist
  (those don't change on a regroup) and re-maps transport/track onto the new group ids.
- **Reducer** (`apply(ChangeEventDto)`), one delta at a time:
  | Event | Effect |
  |---|---|
  | `Volume{speakerId,volume}` | `rooms[speakerId].volume = volume` |
  | `Mute{speakerId,muted}` | `rooms[speakerId].muted = muted` |
  | `Playback{groupId,state}` | `groups[groupId].transport = state` |
  | `Track{groupId,track}` | `groups[groupId].track = track` |
  | `GroupVolume{groupId,volume}` | `groups[groupId].groupVolume = volume` |
  | `GroupMute{groupId,muted}` | `groups[groupId].groupMuted = muted` |
  | `SubscriptionError{speakerId}` | `rooms[speakerId].online = false` |
  | `SubscriptionRecovered{speakerId}` | `rooms[speakerId].online = true` |
  | `TopologyChanged` | no-op here — handled by `topologyController` → re-discover → new `Topology` |
- **Cold start:** rely on the SDK's SUBSCRIBE-NOTIFY seed (~1 s, per ARCHITECTURE § State ownership)
  as primary. A field is `null` until its first event lands → skeleton. (`speaker_state` per-speaker
  seed is an available optimization but is **not** in v0.6.0 unless dogfooding shows cold-start lag.)
- **Lifecycle is already solved upstream.** The Notifier rides the existing `wireGenerationProvider`
  re-subscribe and `topologyController` regroup-follow; it adds **no** new lifecycle edge cases.

### 2.3 Derived selectors

- `sourcesProvider` — ports `sourcesFromRooms`: a **Source** is a group whose `transport ∈ {Playing,
  Paused, Transitioning}` OR `track != null` (i.e. has an active/resumable stream); `Stopped`/idle/off
  are not sources. `label` = member room names joined with " + "; `memberCount` = members.length.
- Per-entity reads use `select`/family (`householdProvider.select((h) => h.rooms[id])`) so a Volume
  event for one room rebuilds **only that card**, not the whole list. This is load-bearing for the
  per-room sliders.
- **Value equality is load-bearing for `select`.** Model types must compare by *value*, including
  collection fields — `GroupState.memberIds` (a `List`) needs `listEquals` in `==`/`hashCode`, not a
  bare `Object.hash(list)` (identity for collections). Without it a value-equal rebuild is treated as
  changed, every event rebuilds every card, and the granular `select` is defeated.

### 2.4 Commands — optimistic + LAN-polite

Command facades ([`playback.dart`](../../../app/lib/src/state/playback.dart),
[`grouping.dart`](../../../app/lib/src/state/grouping.dart)) gain a thin reconciliation wrapper:

- **Optimistic local update first**, then fire the FRB command, then let the authoritative event
  reconcile; on `CommandError`, roll back to last-known.
- **Volume is throttled** (the §3 LAN-politeness non-negotiable): dragging a slider updates the UI
  immediately every frame but sends at most ~1 SOAP command / 150 ms (trailing) + a final send on drag
  end. **Never one command per pixel.** Same for group volume.
- play/pause toggles transport optimistically (`Playing ↔ Paused`) and reconciles on the next
  `Playback` event.
- **No-op sets produce no event** (Sonos suppresses unchanged values — sonos-notes § Group ops). An
  optimistic value must therefore be **self-sufficient**: never revert it for lack of an echo.
  Reconcile only when a *different* authoritative value arrives; roll back **only** on `CommandError`.
  A `CommandError::NotFound` (stale `GroupId` after a regroup) triggers a re-discover, not a silent
  rollback.

## 3. Theming (`app/lib/src/theme/`)

Faithful translation of [`design-tokens.json`](../../design-system/handoff/design-tokens.json).

- `tokens.dart` — spacing/radius/type/elevation constants (named steps, not literals).
- `oto_colors.dart` — an `OtoColors` `ThemeExtension` carrying the non-Material roles
  (`ink2/inkMute/inkFaint/fill/fillStrong/line/lineStrong/success/danger/spotify/accentSoft`). Inks
  are **one base color at descending alpha** (`base.withOpacity(a)`), not four constants.
  **`inkFaint` is decorative only** — never used for text a user must read.
- `accent.dart` — `Accent` enum + resolved light/dark/soft swatches; runtime swap.
- `oto_theme.dart` — builds light + dark `ThemeData` from the above; Geist as the text theme family.
- **Two themes only** (light + dark; dark is a true `#0e0e10`). Accent selectable.
- Geist + Geist Mono TTFs bundled under `app/assets/fonts/` (declared in `pubspec.yaml`).

## 6. Home screen (`app/lib/src/ui/home/`)

One screen, two layouts via the header toggle (persisted). Both bind to `householdProvider` /
`sourcesProvider` — never hand-authored data. Faithful to `hifi-unified.jsx` (`V3HomeCards` /
`V3HomeStack` / `V3GroupCard` / `V3BottomStrip`).

- **Composition (group vs solo).** Home iterates the household's **groups**: a multi-room group
  (`memberIds.length > 1`) renders as **one merged group card**; a solo room (length 1) renders as a
  **room card (Cards) / row (Stack)**. A grouped room therefore appears **only** inside its group card,
  never also as a standalone room card. This resolves the prototype-vs-HANDOFF divergence
  (`V3HomeCards` renders every room individually with a group *badge*; HANDOFF §2 defines the merged
  group card as the group's Home surface) in favour of **HANDOFF §2 / the source model**. The group
  *badge* on a solo room is therefore unused in v0.6.0; group membership is conveyed by the group card.
- **Header** — oto wordmark + mark, "Speakers" title, `N rooms · M playing` subtitle (derived),
  Cards/Stack toggle, gear → Settings (stub route). The search icon is **omitted** in v0.6.0 (search is
  deferred; no dead controls — consistent with §1) and re-added when search lands.
- **Room card (Cards) / row (Stack)** — identity + group badge, live now-playing (the room's *group*
  track + art), per-room volume slider (optimistic + throttled), play/pause.
- **Merged group card** — one source: shared now-playing + **one** transport, group-master volume +
  nested per-room levels capped at 4 + "+N more" (→ Room detail in v0.6.1; in v0.6.0 the overflow
  control is present but its target is stubbed).
- **Adaptive bottom strip** — derived from `sourcesProvider`: 0 → nothing; 1 → floating mini-player;
  2+ → upward-growing stack, **one row per active source, uncapped** (no "manage all" sheet in
  v0.6.0). Per-source play/pause; row taps through to that source's Now Playing.

### Resolved behaviors
- **Idle-room play button = resume-only.** Active when the room's group has resumable content
  (`transport ∈ {Playing,Paused,Transitioning}` or `track != null`). A truly-idle room (Stopped, no
  track) shows "Idle" with **no** actionable start — oto has no source picker. (The prototype's
  "start an idle room" framing is the one place the design overreaches the backend.)
- **Powered-off rooms** render dimmed, no controls (as designed).

## 7. Now Playing screen (`app/lib/src/ui/now_playing/`)

Faithful to `V3NowPlaying`, minus unbacked controls.

- Header: down-chevron (pop), "Playing on <source label>", queue icon → **omitted** (queue deferred).
- Album art (`Track.artUri`, gradient/placeholder fallback when null), title/artist/album.
- **Read-only progress** — duration is known (`Track.durationSecs`); **position is NOT delivered by
  the backend** (deliberately un-watched — polling-derived; `oto-wire/src/events.rs:383`, sonos-notes
  § Event model). The cache's `position` is structurally `None`. So the UI **derives position
  locally**: anchor position 0 at each **`Track` change** and advance by wall-clock while `Playing`;
  on **pause → resume re-anchor from the frozen position** (never reset to 0 on resume); freeze on
  `Paused`. (Re-anchoring only on track change — not on every `Playback→playing` — is what keeps a
  normal pause/resume from snapping the bar back to 0.) **Not scrubbable** (no `Seek`). **Known limitation
  (validate):** a mid-track join has no position anchor (the seed `Playback` carries none) → the bar
  starts at 0 and self-corrects on the next track; an on-demand `get_position_info` anchor is a
  deferred refinement (small capability work, not v0.6.0). No shuffle/repeat (no `SetPlayMode`).
- Transport: prev / **play-pause** / next (the three backed controls), centered.
- Group volume card: group-master slider (optimistic+throttled) + per-room level read-outs.
- "Spotify Connect · from iPhone" source-origin pill → **omitted** (origin not exposed by the backend;
  revisit if/when metadata parsing lands).

## 11. Testing strategy

- **Unit (no Flutter):** `sourcesFromRooms` derivation; the `Household` reducer (each `ChangeEventDto`
  → expected state, incl. regroup re-map + per-speaker preserve); optimistic+reconcile + volume
  throttle; `PrefsRepository`.
- **Widget:** room card/row, group card (2/3/4/6-room cap), bottom strip (0/1/2+ sources), Now
  Playing — pumped against a fixture `Household`.
- **Golden:** themed cards + Now Playing in light/dark (and at least the default accent) — catches
  theming regressions.
- **Integration (LAN-free):** extend `app/integration_test/` via the `dev_discover_mock` +
  `dev_push_*` FRB seam — drive discovery + a sequence of events, assert the Home/Now-Playing UI
  reflects them (incl. a regroup). Mirrors the existing `v0_4_events_test.dart` pattern.
- Gates: `just gen` (FRB/Riverpod codegen) → `just check` → `just test`; UI verified manually in
  `flutter run` on Windows + a real Android device.

## 12. Acceptance criteria (v0.6.0, end-to-end)

1. `discover()` → Home shows real rooms/groups; volume + now-playing populate from live events within
   ~1 s; no fake zeros during cold-start.
2. Cards/Stack toggle works and **persists** across restarts.
3. A volume slider moves the speaker (throttled, optimistic UI); a group-master slider moves the
   group; mute works.
4. Per-source play/pause works from Home and the bottom strip; the strip is derived (0/1/2+ adaptive).
5. Opening Now Playing shows live transport + group volume + per-room levels; prev/next/play-pause
   work; progress is shown read-only.
6. A regroup (from the Sonos app or oto's future editor) is followed live (rooms re-group, sources
   re-derive) with no stale routing.
7. Light/dark + accent switch live and persist.
8. Builds + runs on Windows desktop and Android (API 35+); `just check` + `just test` green.

## 14. Sonos-notes alignment & validation items

Cross-checked against [sonos-notes.md](../../sonos-notes.md). The UI inherits these hardware-confirmed
behaviors; each must be honored in the build and **validated** in the test + dogfood pass. Items not
previously spelled out for the UI layer are flagged **NEW**.

| # | Behavior (sonos-notes ref) | v0.6.0 handling | Validate |
|---|---|---|---|
| 1 | **Position is not evented** — polling-derived, deliberately un-watched (§ Event model; `events.rs:383`). **NEW:** no mid-track anchor (cache `position` is structurally `None`). | Derive locally: anchor 0 at each **`Track` change** + wall-clock while `Playing`; **re-anchor from the frozen position on resume** (NOT 0 — re-anchoring on every `Playback→playing` would snap the bar back); freeze on pause. | Ticks while playing; pause→resume keeps position (no snap-to-0); skip resets to 0; mid-track-join start-at-0 self-corrects. |
| 2 | **Double `Track` events** + ~23 group-vol + rapid `Volume` events; last-wins ~200 ms (§ Reactive-vs-NOTIFY traces; § Group ops). | Idempotent reducer overwrite = natural last-wins; granular `select` rebuilds keep it cheap. | No flicker/thrash on rapid volume drag or track skip; resolved metadata wins over intermediate. |
| 3 | **`Transitioning`** appears on skip / play-start (§ traces). | Treat as in-between (keep last transport / subtle loading), never "unknown"; counts as an active source. | Transitioning never renders a broken/unknown control. |
| 4 | **No-change → no NOTIFY** (§ Group ops). | Optimistic value self-sufficient; never revert on missing echo; reconcile on a *different* value; roll back on error only. | Setting volume to the current value leaves the UI correct (no spurious revert). |
| 5 | **Group-vol change also fires per-member `Volume`** ~6 ms (§ Group volume propagation). | Group vol from `GroupVolume`; per-room from `Volume`. Member sliders move with the master (correct). | Group-master drag moves member sliders coherently. |
| 6 | **Per-speaker seed is non-uniform** — some models don't seed until a real change (§ Per-speaker seed NOTIFY). | Tolerate indefinite `None` (skeleton); no "seed within X" assumption. | A quiet speaker shows skeleton, not a fake 0; fills on first real change. |
| 7 | **Stale `GroupId` → `NotFound`** freshness contract (§ Identifiers). | On `CommandError::NotFound`, re-discover; don't silently drop. | A command issued mid-regroup recovers via re-discover. |
| 8 | **Write rejection = HTTP 500 → native `WireError::Backend` → Dart `CommandError_Sonos`** (Pause-when-stopped, Previous-at-start, idle `play` on empty queue) (§ Error mapping; § Operation table). The Dart FRB surface has only `CommandError.notFound/network/sonos` — there is **no** `Backend` variant Dart-side. | Optimistic action rolls back on `CommandError_Sonos` (device rejected) or `CommandError_Network` (unreachable); the resume-only idle button errors harmlessly if mis-gated. | Prev at track start / play on a truly-idle room → graceful no-op, UI stays consistent. |
