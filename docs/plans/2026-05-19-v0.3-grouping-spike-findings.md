# v0.3 grouping — ZoneGroupTopology spike findings

**Date:** 2026-05-19 **Context:** De-risk before the v0.3 grouping design. Run on the Windows dev box (LAN-attached; unicast SOAP to known IPs — not the multicast SSDP that AGENTS.md §5 gates). Source authority: `sonos-api-0.5.2/src/services/zone_group_topology/{operations,events}.rs`.

**Verdict: hypothesis confirmed.** Direct-SOAP `GetZoneGroupState` + the crate's `parse_zone_group_state_xml` is the deterministic, complete, fast topology path that `SonosSystem` (ARCHITECTURE **Open Q1**) was not. **Open Q1 is closed by avoidance** (same strategy as v0.1/v0.2: own deterministic data, no `SonosSystem`). The long-deferred bonded-speaker question (**Open Q4** / oto-core non-goal) is answered.

## Findings

- **Q1 — dispatch/sync.** ✅ `zone_group_topology::get_zone_group_state() .build()` + `SonosClient::execute_enhanced(ip, op)` → `GetZoneGroupStateResponse { zone_group_state: String }`. Blocking, no tokio, **7–40 ms** (vs. `SonosSystem::new()`'s 3–5 s).
- **Q2 — determinism + completeness (vs. Open Q1).** ✅ **Decisive.** 50/50 successful calls across two distinct topologies returned the **complete** household, **count-stable**, 1 XML variant **per speaker**. The exact opposite of the SonosSystem path (1-of-4, flapping 0↔1). Per-network parity holds (every live speaker reports the same household — `ServiceScope::PerNetwork`). **Caveat:** the XML is *not* byte-identical *across* speakers — `ZoneGroup`/member order is **query-relative** (the queried speaker's own group/element tends to come first) and a few volatile attrs differ (`MicEnabled`, `ChannelFreq`). The *logical* topology is identical; compare on the parsed model, never raw XML.
- **Q3 — parse strategy (the DIDL-equivalent).** ✅ **Win.** `parse_zone_group_state_xml(&str) -> Result<Vec<ZoneGroupInfo>>` (re-exported from `zone_group_topology`) decodes the **control- response** string perfectly — coordinator, id, members, **and nested satellites** — on every call. **Unlike DIDL, oto-wire needs no ZoneGroupState XML parser of its own.** Caveat: it **drops `<VanishedDevices>`** (the offline LR surround is in raw XML, absent from the parsed `Vec`). Fine for v0.3 (don't surface offline units); `ZoneGroupTopologyState::vanished_devices()` is the escape hatch if ever needed (it is not, for v0.3).
- **Q4 — coordinator + GroupId + bonded (Open Q4).** ✅
  - `ZoneGroup@Coordinator` = UUID; `ZoneGroup@ID` = `RINCON_…:N` (e.g. `RINCON_542A1B9463A801400:3426502563`) — matches the discovery-spike `GroupId` observation.
  - `coordinator ∈ members` held in all groups → validates oto-core **D3** *semantically* — but see directive 3: the parser does **not** emit members coordinator-first.
  - **Bonded HT set = one `ZoneGroupMember` (the primary) with nested `<Satellite>` children** (`Invisible="1"`, `HTSatChanMapSet` channel role e.g. `…BE01400:RR`). `parse_zone_group_state_xml` folds them into `ZoneGroupMemberInfo.satellites`. A grouped member keeps its satellites (Run B: Beam+sat joined Kitchen → 2 members, Beam member `satellites=1`). **This means ZoneGroupTopology automatically fixes the v0.1 bug** (bonded surrounds listed as standalone players, because v0.1 used raw SSDP device descriptions) — and confirms oto-core **D5**/non-goal: satellites are hidden behind the primary, share its `RoomName`, not separate entities.
- **Q5 — the v0.2 seam generalizes.** ✅ Against a real 2-room group, `GroupId → Coordinator UUID → member.location → IP → execute_enhanced(play)` → **Ok**. The v0.2 `Wire` signatures are **unchanged**; v0.3 changes *only* the resolution (real coordinator from topology vs. v0.2 group-of-one). *Caveat:* the group was already playing, so this confirms dispatch + acceptance at the real multi-room coordinator (the strongest the seam needs); synchronized multi-room audio was user-observed.
- **Q6 — one-shot suffices.** ✅ App-side re-grouping (Run A 2 groups → Run B 1 group) is **immediately and deterministically** reflected in a fresh one-shot `get_zone_group_state` (10/10 stable each). **No `.watch()`/events needed for v0.3.** Confirms the milestone split: reactive topology events stay v0.4 (Open Q6 / event-suppression constraint does not apply to v0.3's re-fetch model).
- **Extra — VanishedDevices is honest.** `.115` in `<VanishedDevices Reason="UNKNOWN" LastSeenUTC=…>` is a genuinely powered-off unit (user-confirmed: unplugged), **not a library defect**. Corroborates Q2 and explains the v0.1 discovery-spike device-count discrepancy (`.115`/`.187` = bonded/asleep).

## ZoneGroupState → `oto_core` mapping (feeds the v0.3 design)

| Source (`ZoneGroupInfo` / member) | `oto_core` | Note |
|---|---|---|
| `ZoneGroupInfo.id` | `GroupId` | `RINCON_…:N`, opaque |
| `ZoneGroupInfo.coordinator` (UUID) | `Group.coordinator: SpeakerId` | |
| `members[].uuid` | `SpeakerId` | |
| `members[].zone_name` | `Speaker.room_name` | |
| `members[].location` | → host → `IpAddr` | same id→addr cache as v0.2 |
| `members[].satellites[]` (`Invisible="1"`) | **folded into the primary `Speaker`** | not separate speakers (D5) |
| `<VanishedDevices>` | ignored | offline; parser drops it anyway |

## Directives for the v0.3 grouping design (the §7 gate)

1. **Topology source = direct `sonos_api` `get_zone_group_state` via `execute_enhanced`.** Never `SonosSystem` / `from_discovered_devices` / `ensure_topology` (Open Q1 stays closed by avoidance). Query any one reachable speaker (`PerNetwork`); on failure, fall back to another (the v0.2 `map_sdk_err` already maps unreachable → `WireError::Network` — no new error handling).
2. **Parse with the crate's `parse_zone_group_state_xml`.** Do **not** add a ZoneGroupState parser; `quick-xml` stays DIDL-only. The `sonos-api`/`sonos-sdk` `=0.5.2` pin already covers this surface — no new dependency.
3. **The adapter MUST reorder `members` coordinator-first.** The parser does **not** guarantee it (Run B via `.105`: members were `[Kitchen, LivingRoom(=coordinator)]`). oto-core **D3** requires `members[0] == coordinator` — sort in the adapter; do not trust wire order. Likewise normalize group order (query-relative).
4. **Bonded satellites fold into the primary `Speaker`** (`Invisible="1"` → not surfaced). Channel role (`HTSatChanMapSet`) is **not** needed for v0.3 (YAGNI); revisit only if a UI ever shows surround layout.
5. **v0.3 = one-shot re-fetch on demand. No events/`.watch()`** (→ v0.4, Open Q6). Topology fetch is ~7–40 ms — cheap to re-read before group-addressed commands or on user refresh.
6. **`Wire` signatures are unchanged** (Q5). v0.3 changes only `GroupId`→coordinator resolution. **Open for the design (not the spike):** *where* topology re-fetch lives — a new `Wire::topology()` read vs. extending `discover()` to return real groups. The spike proves the data path is sound either way; this is the v0.3 design call this findings doc gates.
7. **Recommended v0.3 acceptance check:** form a 2-room group → resolve coordinator from topology → command at coordinator → assert all member rooms respond (the Q5 path, automated against `MockWire` + one hardware-gated `#[ignore]` like v0.1/v0.2).
