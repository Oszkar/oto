# v0.3 — Grouping — design

**Date:** 2026-05-19 **Status:** Decided (brainstorm + user sign-off, 2026-05-19). Pins the v0.3 surface before implementation. Point-in-time decision record; the living design is `docs/ARCHITECTURE.md` (updated alongside, as a v0.3 deliverable). Gated by the [ZoneGroupTopology spike findings](2026-05-19-v0.3-grouping-spike-findings.md). **Scope:** v0.3 milestone — real ZoneGroupTopology replacing group-of-one. Reads stay one-shot; live events are v0.4.

## Headline

**The v0.2 seam held. v0.3 is a focused `oto-wire` implementation change with no §7 `Wire`/FRB/`oto-core` surface change.** The only dependency-surface movement is a *reduction* — possibly dropping the `sonos-sdk` `test-support` Cargo feature (Open Q5 closure), the single §7 sign-off item below. Other outputs are ARCHITECTURE.md behavior updates.

Already correctly shaped before this milestone:

- `Wire` trait signatures — its own doc states v0.3 "swaps in real ZoneGroupTopology resolution **without changing these signatures**".
- `oto_core::DiscoverySnapshot { speakers: Vec<SpeakerIdentity>, groups: Vec<GroupIdentity{ id, coordinator, members }> }` — already real-topology-shaped; v0.1 merely fills it group-of-one.
- FRB `Topology` / `DiscoveredSpeaker` / `DiscoveredGroup{ id, coordinator, members }` — already conveys coordinator + members.
- `oto-app` routing, `native/src/map.rs`, the Dart providers.

## Context

v0.1 shipped identity-only discovery (group-of-one). v0.2 shipped playback + one-shot state read, deliberately shaping the `Wire`/DTO seam so v0.3 changes *resolution*, not signatures. The spike ([findings](2026-05-19-v0.3-grouping-spike-findings.md)) confirmed the hypothesis on real hardware: direct-SOAP `sonos_api::services::zone_group_topology::get_zone_group_state` via `SonosClient::execute_enhanced` + the crate's `parse_zone_group_state_xml` is the deterministic, complete, ~7–40 ms topology path that `SonosSystem` (ARCHITECTURE Open Q1) was not. Open Q1 stays closed by avoidance (no `SonosSystem`), the same strategy as v0.1/v0.2.

## Decisions (user sign-off 2026-05-19)

1. **Scope: see + control real groups; group form/break OUT, seam shaped now.** v0.3 reads real ZoneGroupTopology and controls existing groups via the real coordinator. Creating/dissolving groups from oto is a later additive slice — its mutating SOAP (`GroupManagement` / `x-rincon:` `SetAVTransportURI`) was **not** de-risked by the spike and gets its own spike+design when scheduled. No stubs/abstractions added now (YAGNI). The seam is **already present**, documented not coded:
   - the `Wire` trait grows **additively** (v0.2→v0.3 proved this; future `join`/`leave` are non-breaking additions);
   - form/break mutates topology, then the caller re-`discover()`s — exactly the **D3** staleness contract, already the model;
   - per-speaker `id_to_addr` addressing already supports join/leave SOAP targeting.

2. **D1 — speaker source: ZoneGroupTopology-authoritative; `model = None`.** Build `SpeakerIdentity` from the topology's top-level members (single authoritative source ⇒ the v0.1 bonded-as-standalone bug is fixed *by construction*, not by reconciliation logic). `ZoneGroupMemberInfo` carries `uuid`, `zone_name` (the Sonos room label — oto-core D5), `location` (→ IP) but **no model** (spike-confirmed: live members/satellites have no Model attr; only `<VanishedDevices>` does). `model: Option<String>` **stays in the types/DTO**, emitted `None`, so v0.5 can repopulate via a bounded per-member device-description fetch with **zero type/FRB change**. Drops `to_devices`/`DeviceDescription` from the identity path → **narrows Open Q5** (the fragile `test-support`-gated `sonos_discovery` surface can leave the identity path; success of `get_zone_group_state` on a responder *is* the "it's a Sonos" proof). *Rejected — 1b (keep device-desc for `model`):* two-source reconciliation (UDN↔UUID, mismatch handling) = more code/edge-cases, the bonded fix becomes logic-dependent, more SOAP per `discover()`, and the Open Q5 pin stays load-bearing. `model` is cosmetic, unused until a v0.5 UI, and cheaply + more-safely restorable then.

3. **D2 — transport read resolves to the coordinator (signature unchanged).** With real groups, transport lives on the coordinator (oto-core D2; Sonos semantics). `speaker_state(SpeakerId)` keeps its v0.2 signature: volume/mute read at the speaker itself (per-speaker, correct); transport (`GetTransportInfo`/`GetPositionInfo`) read at the speaker's group's **coordinator**. Solo speaker = its own coordinator ⇒ identical to v0.2. Settles the v0.2 ADR's "revisit at v0.3" item via *resolution*, not a surface change; the full state-shape move (transport off `SpeakerState`) stays a v0.4 concern (when state becomes event-fed). *Rejected:* "document non-coordinator transport as wrong" (ships an incorrect read); "add a group-addressed state read now" (§7 surface change pulling the v0.4 state reshape forward — YAGNI).

4. **D3 — freshness: refresh = re-call `discover()`.** Caches are (re)populated only by `discover()`. Topology changes on app-side regroup (`GroupId` is `RINCON_coord:N`; `N` changes); a stale `GroupId`/`SpeakerId` → `WireError::NotFound` (the existing v0.2 precondition error). The v0.5 UI owns refresh UX. No implicit polling (§3-clean), one-shot — matches the milestone framing. `TODO(v0.5):` optional cache-miss → re-fetch-once → retry self-heal, if staleness proves annoying in real use. *Rejected for v0.3:* per-command topology re-fetch (+1 SOAP/command; muddies the discover-populates/commands-use-cache model); cache+miss-retry (more adapter state — deferred as the v0.5 TODO).

State-and-proceed (findings-decided, AGENTS.md §0 low-impact): fold `Invisible` satellites into the primary speaker (not separate speakers — oto-core D5); ignore `<VanishedDevices>` (the parser drops them); reorder `members` coordinator-first (spike directive — the parser does **not** guarantee it; oto-core D3).

## Surface

### `oto-wire` (the whole milestone lives here)

**`discover()` pipeline.** `ssdp::discover_locations` → for each responder, extract IP → `get_zone_group_state` until one succeeds (`ServiceScope::PerNetwork` ⇒ any working speaker returns the whole household; D1 multi-responder fallback handles an asleep/vanished first responder — spike: `.115` failed, `.103/.105/.187` all succeeded) → `parse_zone_group_state_xml` → `to_snapshot`.

**`to_snapshot(Vec<ZoneGroupInfo>) -> DiscoverySnapshot`** (replaces the group-of-one builder):

- **speakers** — each top-level `ZoneGroupMemberInfo` → `SpeakerIdentity { id: SpeakerId::new(member.uuid), room_name: member.zone_name, model: None, ip: extract_ip(&member.location) .parse() }` (reuse the adapter's existing `extract_ip`). ZoneGroupState UUIDs are **already bare `RINCON_…`** (no `uuid:` strip, unlike the device-desc UDN path). Satellites (`member.satellites`, `Invisible="1"`) are **not** emitted. An unparseable `location` IP → skip that member (defensive, mirrors v0.1).
- **groups** — each `ZoneGroupInfo` → `GroupIdentity { id: GroupId::new(info.id), coordinator: SpeakerId::new(info.coordinator), members }`, where `members` is the member UUIDs **with the coordinator moved to index 0** (oto-core D3) and the rest in wire order. Coordinator-absent-from-members ⇒ anomalous → skip the group (defensive; spike confirmed it is always present).
- `<VanishedDevices>` — ignored (`parse_zone_group_state_xml` already drops them; no oto-wire handling needed).

**`populate_caches`** — add a `speaker_to_coordinator: Mutex<HashMap< SpeakerId, SpeakerId>>` populated from the snapshot (every member → its group's coordinator) for D2. `id_to_addr` and `group_to_coordinator` are unchanged — already correct for real multi-member groups (a real coordinator is now a real other speaker; resolution is the same lookup).

**`control::speaker_state`** — volume/mute SOAP at the speaker's own `SocketAddr`; transport SOAP (`GetTransportInfo`/`GetPositionInfo`) at the coordinator's `SocketAddr` (resolve `speaker → speaker_to_coordinator → resolve_speaker`). Internal split of the addr argument; the `Wire::speaker_state` signature and `SpeakerState` shape are unchanged.

**Removed:** `to_devices` and the `DeviceDescription` identity path (D1). SSDP still finds responders; `get_zone_group_state` success is the Sonos-ness proof.

### Unchanged

`Wire` trait, all `oto_core` types (`DiscoverySnapshot`, `SpeakerIdentity`, `GroupIdentity`, `SpeakerState`, `WireError`), FRB DTOs, `native/src/map.rs`, `oto-app` command routing, Dart providers. No `just gen` needed (no `api.rs`/`@riverpod` change).

## Tests

- **`oto-mock`** — extend the fixture to a real multi-room group + a bonded primary (satellite folded) + a standalone. `discover()` returns a real `DiscoverySnapshot`; `speaker_state` on a grouped **non-coordinator** member reflects the **coordinator's** transport (D2) while returning that member's own volume/mute. All LAN-free.
- **`oto-wire` unit** — `to_snapshot` against **captured real ZoneGroupState XML from the spike**: solo, 2-room group, bonded-with-active-satellite, vanished-device present, and the `.105`-style **coordinator-not-first** input (asserts the D3 reorder). Bakes the spike evidence into a regression test; no LAN.
- **`native/tests/` e2e** — extends the v0.1/v0.2 pattern (drive `oto-app` + `MockWire` through the real `oto_native::map`): a multi-member `DiscoveredGroup` crosses the DTO map; a grouped non-coordinator `speaker_state` returns the group transport.
- **Hardware-gated `#[ignore]`** (sibling of v0.1/v0.2) — real `discover()` → real groups; the findings directive-7 acceptance (form a group in the Sonos app → command at the resolved coordinator → all member rooms respond). User-run, like v0.1 Task 8 / v0.2.

## §7 sign-offs

Per AGENTS.md §7, the *only* item needing sign-off:

- **Dropping the `sonos-sdk` `test-support` Cargo feature** from `native/Cargo.toml` **iff** removing `DeviceDescription` from the identity path leaves no other `sonos_discovery` use-site (verified during implementation). This is a dependency-surface change and an **Open Q5 closure**. The `=0.5.2` pin stays; `sonos-api` stays a direct dep. If a use-site remains, the feature stays and Open Q5 is *narrowed*, not closed — recorded either way in the plan/PR.

No `Wire`/FRB/`oto-core` surface sign-off (the surface is unchanged — the headline). The `discover()` behavior change (group-of-one → real topology) and the D2 transport resolution are documented ARCHITECTURE.md updates, not surface sign-offs.

## Validation bar (v0.3 "done")

The `native/tests/` e2e drives `discover()` + `speaker_state` through `oto-app` against the **stateful** `MockWire` with a real multi-room/bonded fixture and asserts: a multi-member `DiscoveredGroup` crosses the map; a grouped non-coordinator's `speaker_state` returns the coordinator's transport + its own volume/mute — proving the bar without a LAN or UI. `just check` + `just test` + `cargo deny` green; `just gen` unaffected (no FRB change). A real-hardware Windows run (the directive-7 acceptance) is the user-run step, like v0.1/v0.2.
