# v0.2 — Playback control + state read — design

**Date:** 2026-05-17 **Status:** Decided (brainstorm + user sign-off, 2026-05-17). Pins the v0.2 FRB/`Wire`/`oto-core` surface before implementation. The point-in-time decision record; the living design is `docs/ARCHITECTURE.md` (updated alongside, as a v0.2 deliverable). **Scope:** v0.2 milestone — playback control + a one-shot state read, proven end-to-end through the Rust↔Dart bridge, verifiable without the real UI (UI is v0.4).

## Context

v0.2 (README milestone ladder) = **playback control** — play/pause/next/ prev, volume, mute, and reading current state. v0.1 shipped identity-only LAN discovery: `oto-core` domain + identity types, the one-method `Wire` trait, `oto-wire` (own multi-NIC SSDP + `ureq` device-description fetch + `sonos_discovery` adapter), `oto-mock`, `oto-app` (holds the active `Wire`, replace-on-success), and the non-sync FRB `discover()`.

Hardware/source constraints feeding this design (verified 2026-05-17 against the pinned `sonos-sdk =0.5.2` source, not guessed):

- `Speaker::{play,pause,stop,next,previous,seek,set_volume,set_mute, set_relative_volume}` all exist, all **sync**, all `-> Result<(), SdkError>`. **Zero `async fn`** in the `sonos-sdk` umbrella surface — the sync `Wire` boundary holds; no tokio in oto's own code.
- Property reads are `get()` (cached `Option`) / `fetch()` (sync SOAP) / `watch()` (subscribe). Per-property; no bulk fetch.
- **Load-bearing problem:** obtaining a `Speaker`/`Group` to call `.play()` on requires a `SonosSystem`; `from_discovered_devices` runs `ensure_topology()`, the exact path v0.1 hardware-proved lazy / non-deterministic (1 of 4 speakers, flapping 0↔1 — ARCHITECTURE Open Q1). There is a verified escape hatch: `sonos_api::SonosClient:: execute_enhanced(ip, op)` issues SOAP directly to an IP with **no `SonosSystem`, no topology**. v0.1's discovery snapshot already yields every speaker's IP; group-of-one means *target = the speaker itself*.

## Decisions

The five brainstorm decisions (user sign-off 2026-05-17):

1. **Grouping: group-of-one now, seam shaped for v0.3.** v0.2 controls each discovered speaker as its own group-of-one. Real ZoneGroupTopology (multi-room groups, bonded pairs/surrounds, coordinator/topology-change events) stays **v0.3**. The `Wire`/DTO surface is shaped so v0.3 changes *resolution*, not signatures.
2. **State read: one snapshot command per speaker, `Option<T>` fields** (Approach A — see ADR below). `speaker_state(SpeakerId) -> SpeakerState`. Live event streams stay **v0.3**, so v0.2 reads are one-shot SOAP fetches.
3. **Dart: mirror v0.1.** Thin Riverpod providers + headless Flutter tests for the new surface; remove the `greet` demo scaffold; no real screens (UI is v0.4).
4. **Control path: low-level direct SOAP via `sonos_api::SonosClient`, no `SonosSystem`** (Approach 1), **de-risked by a throwaway spike first** — same flow as the v0.1 discovery spike, matching the project's spike-first, "build from our own deterministic device data; don't trust sonos-sdk topology" philosophy.
5. **Commands are non-sync (Dart `Future`), like `discover()`.** Every v0.2 command is a blocking SOAP round-trip (~tens–hundreds of ms). This is an explicit delta from v0.1 ARCHITECTURE's "commands are synchronous Dart→Rust calls; discovery is the documented exception" — the sync-command model assumed non-blocking commands; hardware proves none are. Recorded in ARCHITECTURE.md as a v0.2 deliverable.

### ADR — state-read shape (user-requested record; also lands as a short
note in ARCHITECTURE.md, "revisit in v0.3")

The fact that shaped this: each read is a blocking SOAP round-trip; a full state read ≈ 4 calls (`GetVolume`, `GetMute`, `GetTransportInfo`, `GetPositionInfo`). In **v0.3** "current state" stops being SOAP-fetched and becomes a read of the event-fed cache — so the v0.2 read surface is partly transitional; the design question is *which shape survives the v0.3 fetch→cache swap unchanged*.

| | Pros | Cons / Risks |
|---|---|---|
| **A. Snapshot command per speaker** (chosen) | Mirrors the proven v0.1 `discover→snapshot→FutureProvider` pattern; smallest `Wire` seam (one method); **best v0.3 survival** — signature unchanged when the impl flips fetch→cache; one mock method | Coarse (no selective refresh); reading all speakers = N×4 SOAP serial. Partial-failure forces a decision — answered by `Option<T>` fields, which is *honest* (matches SDK `get()` and v0.3 cold cache) |
| B. Granular per-property reads | 1:1 with SDK handles; selective refresh | 3–4× the FRB/`Wire`/mock surface *now* for a v0.4-UI need (YAGNI); more §7 surface to carry across the v0.3 rework |
| C. Fold state into `discover()` | Fewer round-trips | Worst v0.3 survival; couples state to the slow ~3–5s blocking discovery; the contract becomes vestigial when state is continuous |
| (D. Cache in `oto-app` + refresh) | — | Pulls v0.3's event-cache forward = scope creep; excluded |

**Chosen: A with `Option<T>` fields. Revisit at v0.3** when state moves to the event-fed cache (the read impl changes behind the unchanged `Wire` signature; transport re-addressing — see below — is the main open question to settle then).

## Surface

### Phase 0 — throwaway spike (gates the §7 commit)

`native/crates/wire/examples/playback_spike.rs`, run against a known speaker IP on a real LAN; throwaway, mirrors `examples/spike.rs`. Findings → `docs/plans/2026-05-17-playback-spike-findings.md`, feeding the implementation plan. No product code committed from the spike.

Open questions the spike must answer (do not guess at plan time):

1. Exact `sonos_api` operation-builder API + response types for the 6 commands (Play/Pause/Next/Previous + SetVolume/SetMute) and the 4 state GETs (GetVolume/GetMute/GetTransportInfo/GetPositionInfo), including the `InstanceID` convention.
2. **DIDL-Lite track metadata:** does `sonos_api` decode `CurrentTrackMetaData` into a struct, or must `oto-wire` parse the embedded XML itself? (Largest unknown — drives `Track` mapping cost.)
3. `SdkError` shape → `WireError` mapping (which variants actually occur: transport/timeout vs SOAP fault vs parse).
4. Volume width: SOAP `0..=100` ↔ `oto_core::Volume` (`u8`, `0..=100`) confirmed; clamp boundary behaviour.
5. Confirm fully sync — no tokio reactor needed calling `sonos_api` directly (the umbrella surface has zero `async fn`; confirm the `sonos-api`/`soap-client` path is sync `ureq`).

### `oto-core` (§7 — new domain surface)

```rust
// new — the v0.2 read DTO at the domain layer
pub struct SpeakerState {
    pub volume: Option<Volume>,
    pub muted: Option<bool>,
    pub transport: Option<TransportState>, // reuses existing type
}                                          // (Track + position live there)

// WireError gains one variant
pub enum WireError {
    Network(String),
    NoDevicesFound,
    Backend(String),
    NotFound(String), // unknown speaker/group id (precondition)
}
```

`Option` fields = honest partial-failure: a snapshot does ~4 SOAP calls; any subset may fail. Matches SDK `get() -> Option` and the v0.3 cold cache.

`Speaker`/`Group` structs stay **as-is, deliberately still forward-looking** for v0.3 (real topology + reactive `Group`). v0.2 *reads state* via `SpeakerState`; it does **not** unify `Speaker`/`SpeakerIdentity` (YAGNI — no v0.2 consumer needs it). This clarifies the v0.1 doc's "v0.2 grows `Speaker` around `SpeakerIdentity`" note: v0.2 populates state through reads, it does not reshape `Speaker`. Known unused-until-v0.3; revisit then.

### `Wire` trait growth (§7) — typed methods

```rust
pub trait Wire {
    fn discover(&self) -> Result<DiscoverySnapshot, WireError>; // unchanged

    // Playback — addressed by GroupId (Sonos plays per-coordinator).
    fn play(&self, group: &GroupId) -> Result<(), WireError>;
    fn pause(&self, group: &GroupId) -> Result<(), WireError>;
    fn next(&self, group: &GroupId) -> Result<(), WireError>;
    fn previous(&self, group: &GroupId) -> Result<(), WireError>;

    // Per-speaker controls.
    fn set_volume(&self, speaker: &SpeakerId, volume: Volume)
        -> Result<(), WireError>;
    fn set_mute(&self, speaker: &SpeakerId, muted: bool)
        -> Result<(), WireError>;

    // One-shot snapshot read (state-read shape A).
    fn speaker_state(&self, speaker: &SpeakerId)
        -> Result<SpeakerState, WireError>;
}
```

No default methods — `SonosWire` and `MockWire` implement all (keeps the §7 surface explicit and the mock honest).

**Seam for v0.3 = the addressing, not an abstraction layer.** Playback takes `GroupId` (Sonos plays per-coordinator); volume/mute/state take `SpeakerId` (per-speaker). v0.2 `SonosWire` resolves `GroupId → coordinator → IP` trivially (group-of-one: the group's only member *is* its coordinator). **v0.3 changes only that resolution** (real coordinator from ZoneGroupTopology); these signatures do not change. Open for v0.3: transport state is conceptually per-`Group` (oto-core design D2); v0.2 returns it inside `SpeakerState` (sound for group-of- one). v0.3 re-addresses transport to the group — recorded as the ADR's "revisit at v0.3" item.

### Scope exclusions (stated assumptions, AGENTS.md §0 — low-impact)

- `stop` excluded: README v0.2 lists play/pause/next/prev only; pause is the controller's stop. Trivially addable.
- `set_relative_volume` excluded: absolute `set_volume` only; relative +/- is v0.4 UI ergonomics (YAGNI).

### id→IP addressing (§4 boundary clarification)

`SonosWire` holds an interior-mutable id→addr table (`Mutex<HashMap<…>>`, keeping the trait `&self`; `Send`, no ripple to `oto-app`'s locking), **populated by `discover()`**. A command before discovery, or for an unknown id, returns `WireError::NotFound`.

**Rationale:** "how to reach a device" (IP/port/SOAP) is a *transport* concern → it belongs behind the `Wire` seam in `oto-wire`, the sole `sonos-sdk` integration point (§4.2). `oto-app` stays domain-level and remains the sole owner of *domain* runtime state (§4.4) — it does not learn about IPs.

### `oto-app`

Command-routing fns delegating to the held `Wire` (`play(group)` … `speaker_state(speaker)`): lock the slot, borrow `&dyn Wire`, call, return. Adds the slot accessor the existing `// TODO(v0.2)` in `crates/app/src/lib.rs` anticipates (also lets a test assert a second success replaces the first wire).

**Concurrency (AGENTS.md §3):** the `Mutex<Option<HeldWire>>` is held across the blocking SOAP call. Deliberate: commands are user-initiated and low-frequency; a global serialize *is* the LAN-politeness story (no command storms against the user's speakers). Revisit only if v0.3 events + commands contend. Stated, not premature-optimised.

### FRB surface (§7 — ARCHITECTURE.md updated first)

`native/src/api.rs` stays glue-only (delegate to `oto-app`; the representational map lives in `native/src/map.rs`, testable off-bridge, exactly as v0.1's `to_topology`/`to_discovery_error`).

- **Non-sync** fns (Dart `Future`, FRB worker executor — decision 5), one per command + `speaker_state`: `play/pause/next/previous(group_id: String)`, `set_volume(speaker_id: String, volume: u32)`, `set_mute(speaker_id: String, muted: bool)`, `speaker_state(speaker_id: String) -> SpeakerStateDto`.
- DTOs (FRB-friendly scalars, all `Option`, like `Topology`): `SpeakerStateDto { volume: Option<u32>, muted: Option<bool>, transport: Option<TransportDto> }`, `TransportDto { state: PlaybackStateDto, position_secs: Option<u64>, current_track: Option<TrackDto> }`, `TrackDto { title/artist/album: Option<String>, duration_secs: Option<u64>, art_uri: Option<String>, … }`.
- `enum CommandError { NotFound(String), Network(String), Sonos(String) }` — 1:1 with `WireError` post-map (`Backend → Sonos`, mirroring v0.1's `Backend → Sdk` rename).
- Remove the `greet` demo: `api.rs`, `oto_core::greeting`, `app/lib/main.dart`, `app/lib/src/state/greeting.dart` (+ `.g.dart`), `app/test/smoke_test.dart`. FRB + riverpod regen (`just gen`).

### Dart (mirror v0.1)

Thin Riverpod providers (`app/lib/src/state/`) for the commands + `speakerState`; headless Flutter tests asserting each crosses the bridge against the generated bindings; greet scaffold removed. No real screens.

### Tests

- **Stateful `MockWire`** (the core test-infra growth): an in-memory per-speaker model — commands mutate it, `speaker_state` reflects it (`set_volume(70)` then read = 70; `play` flips `transport.state`). Proves command→state round-trips with **zero LAN**. `discover()` seeds the model from the fixture.
- The `native/tests/` e2e extends the v0.1 pattern (drive `oto-app` + `MockWire`, assert across the real `oto_native::map`), now covering the command + state DTOs.
- A hardware-gated `#[ignore]` playback smoke (sibling of `crates/wire/tests/live_discovery.rs`) — user-run, like v0.1 Task 8.

## §7 sign-offs bundled in this design

Per AGENTS.md §7, these need sign-off before code; this design + the user's spec review is that sign-off:

a. `Wire` trait — +7 methods (§"Wire trait growth"). b. `oto-core` — new `SpeakerState`; `WireError::NotFound`. c. FRB surface — 6 commands + `speaker_state`, the DTOs, `CommandError`; commands **non-sync** (decision 5 — documented ARCHITECTURE delta). d. **Adding `sonos-api` as a direct `oto-wire` dependency**, pinned `=0.5.2` (same pin discipline as `sonos-sdk`; the test-support umbrella stays for discovery's `sonos_discovery::{Device, DeviceDescription}`). The Android `openssl`-vendored hack (`native/Cargo.toml`) stays while `reqwest` remains in-tree via the umbrella discovery still needs. (Exact dep wiring — direct crate vs umbrella re-export — is a spike/plan detail; the *decision to depend* is signed off here.) e. §4 addressing clarification (§"id→IP addressing"): transport addressing lives in `oto-wire`, not `oto-app`.

## Validation bar (v0.2 "done")

The `native/tests/` e2e drives the commands + `speaker_state` through `oto-app` against the **stateful** `MockWire` and asserts the returned `SpeakerStateDto` reflects prior commands — proving the bar without a LAN or the designed UI. Headless Flutter tests prove the providers cross the bridge. A real-hardware Windows run (playback against a live speaker) is the user-run step, like v0.1.

## Out of scope (correctly deferred)

- Real ZoneGroupTopology — multi-room groups, bonded pairs/surrounds, coordinator/topology-change events → v0.3 (ARCHITECTURE Open Q1/Q4).
- The continuous event `Stream` + its pump thread; `.watch()`; the watch-after-`fetch()` suppression (Open Q6) → v0.3.
- `stop`, `set_relative_volume`, seek, queue/transport-source changes → later / as needed.
- Unifying `Speaker`/`SpeakerIdentity`; using the `Speaker`/`Group` structs → v0.3 when real topology needs them.
- Android release SSDP/`MulticastLock` → v0.4 (unchanged from v0.1).
